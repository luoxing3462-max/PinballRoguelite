# UI and Shared Module

Assets/Resources/Prefabs/UI.prefab is the runtime UI root. It owns GameCanvas, CanvasScaler, GraphicRaycaster, EventSystem, StandaloneInputModule, GameplayUiPrefabRegistry, and LevelUiPrefabRegistry. GameRoot loads this prefab before it creates a screen.

Assets/Prefabs/UI/GameplayUI.prefab is the isolated portrait gameplay HUD. Its stable SafeArea hierarchy owns editable `BattleTopArea`, `PinballBoardArea`, and `BottomControlArea`, plus BoardHintText, FloatingFeedbackLayer, and ResultOverlay with VictoryPanel and DefeatPanel. Their RectTransforms are the persisted visual layout authority: runtime code must not set their anchors, size, scale, or positions. SafeAreaFitter maps the outer SafeArea to Screen.safeArea so notches, cutouts, and gesture insets do not cover interactive UI. GameplayUiView binds explicit serialized references and forwards input to GameplayScreen without computing gameplay state; it derives the world camera viewport from PinballBoardArea without changing its RectTransform. Assets/UI/Gameplay/Fonts/GameplayUIFont.asset supplies the temporary Chinese-capable TMP font. GameplayUiPrefabBuilder creates the default prefab and reconnects the runtime UI root registry, but explicit rebuilds replace manual prefab layout.

Assets/Prefabs/UI/LevelMapUI.prefab is the isolated tower-map UI Toolkit system. Its UIDocument references Assets/UI/Toolkit/LevelMap/LevelMap.uxml and its dedicated LevelMapPanelSettings.asset; LevelMapUIController is the lifecycle entry point and references Node.uxml for dynamic VisualTreeAsset node instances. LevelMap.uss and Node.uss keep all static editable styling in UI Builder. It creates only visual route lines and node controls from MapScreen-provided data, forwards selection and placeholder continuation events, and does not decide route legality. LevelUiPrefabRegistry points to this prefab. The legacy LevelUI.prefab remains available only as a non-runtime compatibility artifact; do not use it for new map work.

Assets/Prefabs/UI/MarbleSelectionUI.prefab is the isolated UI Toolkit starting-marble selection system. Its UIDocument references Assets/UI/Toolkit/MarbleSelection/MarbleSelection.uxml and MarbleSelectionPanelSettings.asset; MarbleSelectionUIController owns visual binding while MarbleSelectionScreen remains the two-choice flow bridge. MarbleCard.uxml and MarbleCard.uss provide the reusable card structure. The controller reads MarbleCatalog rather than duplicating marble balance values, and MarbleSelectionArtCatalog references the PSD-exported Sprite assets under Assets/Art/UI/MarbleSelection. Static artboard positions live in UXML/USS for UI Builder editing; runtime code only creates the six data-bound cards and updates selected state/count. MarbleSelectionUiPrefabRegistry connects the independent prefab to the UI root.

TitleScreen, ResultOverlay, and LaunchHoldButton own their respective runtime UI behavior. GameplayUiView owns gameplay-HUD bindings and result-panel presentation, while CombatDisplay only animates its bound combat placeholders. UiFactory creates legacy anchored controls beneath the prefab Canvas for non-gameplay screens. SpriteFactory creates temporary geometric visuals used by gameplay and map screens.

Keep the 750 by 1334 portrait reference layout responsive, with width-priority scaling. UI Toolkit LevelMap and marble-selection dynamic text inherit the shared 方正粗圆_GBK font resource from `Assets/UI/Gameplay/Fonts/方正粗圆_GBK.ttf`; PSD-authored card text remains part of the Sprite artwork. Mouse and touch input share the prefab EventSystem path.
